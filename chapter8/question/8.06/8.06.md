# 研究課題8.6
## 課題内容
次のプログラムをコンパイルし実行してみよう。

main()
{
    int i;
    if( fork() != 0 )
        exit(0);
    for(i = 1 ,  i <= 10 ; i++){
        printf("still here .. \n");
        sleep(i);
    }
    return 0;
}

このプログラムがどのように動作するか、それはどんな仕組みなのかを説明しなさい。
Unixは、ユーザーがプログラムをバックグラウンド実行することを認めている。
このプログラムは、バックグラウンドプロセスとどのくらい似ているか、説明しなさい。

## fork() != 0 のプロセスをexit(0)で終了させる。
fork() != 0 のプロセスをexit(0)で終了させている。
これはforkで生成したプロセス以外は終了させるということなので、
このプログラムを起動した際の親プロセスは即終了される。

子プロセスは親が終了しても強制的に終了されるわけではないため、終了したあとも実行される。
そのため、親が終了して、フロントプロセスがbashに戻されるため、forkでできた子プロセスが
あたかもバックグラウンドで動いているように見える。

## shellのバックグラウンドプロセスとはどう違うのか？
バックグラウンドプロセスはジョブ制御を行っている。
バックグラウンド実行ではシェルがジョブ番号をつけてwaitpidで終了を回収するが、
このプログラムでは子はinitに引き取られ、終了通知もジョブ番号も存在しない。
